A novel tabular-foundation-model-based algorithm

I've been investigating tabular foundation models, which I have found to be very interesting conceptually. Think about tabular foundation models as ChatGPT for datasets. ChatGPT seems to know everything that natural language has to offer because it is a transformer-based architecture thrown at all the textual data we have - all of the internet, books, etc. Therefore, it is extraoardinarily good at next-word completion. Tabular foundation models are similar: we throw a transformer-based architecture at billions of synthetically-generated datasets. Therefore, when presented with a new dataset, it is very good at coming up with predictions for an out-of-sample point.

Tabular foundation models come from a Bayesian inference perspective. However, in this post, I'd like to motivate a kernel regression point of view. This viewpoint is well-motivated by the architectural design of the model, which is why I particularly like it. In modern ML, architectural designs can seem very black-boxy!

In a nutshell, what tabular foundation models do is they embed each row in your context, as well as the query row, and let the query attend to all of these context embeddings. This lends itself naturally to a kernel regression interpretation of tabular foundation models. The query decides how important each context point is towards prediction. This creates a target-aware kernel.

Here's a general retrieval algorithm using tabular foundation models. You can use a (good) tabular foundation model of your choice, denoted TFM.

Algorithm: \(\textbf{SoftRetrieve}(\mathcal{D}, x)\)
Input: \(\mathcal{D} = \{x_1, \ldots, x_n\}\), query point \(x\)
Output: soft retrieval weights over \(\mathcal{D}\) for \(x\)
  1. Run \(\mathrm{TFM}(\text{context} = \mathcal{D},\ \text{queries} = \mathcal{D})\).
  2. For each head \(h\), compute self-attention \(\displaystyle s_h = \frac{1}{n}\sum_{i=1}^{n} \alpha_h(x_i, x_i)\).
  3. Let \(h^\ast = \arg\max_h s_h\).
  4. Run \(\mathrm{TFM}(\text{context} = \mathcal{D},\ \text{query} = x)\).
  5. return \(\alpha_{h^\ast}(\cdot,\, x)\).

In my experiments, I found that these weights this soft retrieval was quite good (details to be added) - the kernel regression estimate that resulted from it was better than LGBM in some cases (in particular the example below), and was very predictive.

Here, we demonstrate this algorithm on a Spotify dataset, where the goal is to predict the popularity of a song. Our TFM of choice is TabICLv2. We found that the average IPR was \(11.86\) (with a context size of \(5000\)), showing that the TFM identifies incredibly tight neighborhoods. This phenomenon is not particular to TabICLv2.

We also try this on a financial dataset of 515 companies, where we predict valuation multiple. (I cheated a bit here, I had Claude choose a target and train a LGBM model much better than baseline. I then used the feature engineering it produced for TabICLv2). Since the dataset was very small, for each point we give the rest 514 points as context, allowing us to create a full graph across the companies. We found that the average IPR was \(27.60\) (with a context size of \(514\)), again showing that the TFM identifies incredibly tight neighborhoods.

I couldn't get enough of trying this on various datasets. The last is a personalized one, built from my Spotify data. It is a dataset on artists and the target is how much I like them.
